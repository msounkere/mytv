## US-34 — Occupation du compte : diagnostic et retrait progressif (codeur c6-a, Go) · A FAIRE
- CA1 Retrait progressif de la patience sur 407 (internal/baux/patience.go, internal/live, internal/vod) : delai initial `bail.reessai` (3 s), puis x2 avec plafond `bail.reessai_max` (defaut 30 s) et gigue (+/- 20 %), sans depasser le budget total `bail.patience_max` ; horloge injectable ; test chronometre : sur 40 s, au plus 5 requetes au fournisseur (au lieu de 13) ; validation de config (`reessai_max >= reessai`).
- CA2 Apres patience epuisee : 503 + `Retry-After` CROISSANT par (session, chaine) selon les echecs consecutifs (15 s, 30 s, 60 s, plafond 60 s) ; remis a zero apres un succes ; code JSON stable + en-tete `X-Mytv-Erreur` (lisible par hls.js). Aucun de ces refus ne declenche d'appel supplementaire au fournisseur par un autre chemin.
- CA3 Diagnostic de l'occupation : quand un 407 persiste (a partir du 2e refus d'une meme demande), le serveur lit `user_info` du fournisseur (InfoCompte : active_cons, max_connections) ; resultat mis en cache `supervision.cache_occupation` (defaut 15 s), UNE seule requete a la fois (singleflight), jamais plus d'un appel par intervalle ; classification : `compte_utilise_ailleurs` (active_cons >= max ET aucun bail mytv actif pour ce fournisseur : Baux.Occupes == 0), `compte_utilise_par_mytv` (un autre bail mytv d'une AUTRE session existe), `compte_occupe` (indetermine, user_info indisponible ou active_cons < max : le fournisseur garde la place quelques instants) ; ces codes remplacent le code generique dans la reponse 503 ; contrat docs/openapi.yaml + test de conformite.
- CA4 Coupure en cours de lecture : un 407/401/403 apparaissant apres des succes consecutifs sur la meme chaine est journalise « connexion reprise par un autre appareil » (WARN, une fois par episode), compte dans une metrique `live_prises_de_place_total`, et expose dans `GET /admin/fournisseurs` (`occupation: libre|mytv|ailleurs`, `depuis`, `derniere_prise`) ; la supervision ne marque PAS le compte « refuse » pour cela (le 401/403 de SEGMENT reste `segment_expire`, cf. lot 4).
- CA5 Faux fournisseur (internal/testutil/fauxiptv) etendu : `user_info` avec `active_cons`/`max_connections` coherents avec l'etat du mode « une seule connexion », et un « occupant externe » programmable (un client qui prend la place sans passer par mytv, pour une duree donnee) ; scenarios : occupant externe pendant 30 s puis libere (reprise sans martelage : nombre d'appels amont compte), occupant externe qui prend la place en pleine lecture (coupure detectee, classification `ailleurs`), deux sessions mytv concurrentes (`par_mytv`), user_info en panne (`compte_occupe`).
- CA6 Aucune regression : zapping x10 normal inchange (tests existants verts), cout nul quand il n'y a pas de 407.
